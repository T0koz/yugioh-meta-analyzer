## Important

**I1. Garde-fou : contournements par la syntaxe du shell** — `.claude/hooks/garde_fou.py:111-136` (`analyser_segment`),
`:87-108` (`analyser_git`). Reproduit avec `analyser()` : ces commandes passent (`pass`) au lieu d'être refusées :
`{ git push; }`, `! git push`, `if true; then git push; fi` (le premier mot du segment est `{`, `!`, `then`, `do`, pas `git`) ;
`bash -lc 'git push'` (`"-c" in args` ne voit pas `-lc`) ; `eval 'git push'` ; `sudo -u root git push` (la valeur de `-u` est
prise pour la commande) ; `nice -n 5 git push`, `env -u X git push` ; `git commit -nm x` (= `--no-verify`, la lettre `m` exclut la
règle `-n`) ; `git -c alias.p=push p`. Risque : accidentel plutôt que malveillant, mais c'est la seule barrière avant un push sur
un dépôt public sans revue. Correctif : ignorer `{`, `!`, `then`, `do`, `else` en tête de segment ; accepter les options groupées
contenant `c` pour les shells ; traiter `eval` comme un shell ; sauter la valeur des options de `sudo`/`nice`/`env` ; pour `commit`,
refuser toute option courte groupée contenant `n` sauf si la lettre qui suit consomme une valeur (`-m`, `-F`, `-C`, `-c`) *avant* le `n`.

**I2. Garde-fou : faux positif connu, reproduit** — `garde_fou.py:52-54` (`sous_commandes`) et `segments`. Une commande dont une
chaîne entre guillemets contient `` `git push` ``, ou dont le corps d'un heredoc contient une ligne `bash -c 'git push'`, est
refusée : chaque ligne du heredoc est traitée comme une commande, et les accents graves d'un mot entre guillemets sont exécutés
par l'analyse. Constat : mon propre script de test (un heredoc Python) a été bloqué. Correctif : repérer les `<<[-]'?MOT'?` et
ignorer le corps jusqu'à `MOT` ; ne chercher les accents graves que dans les mots entre guillemets doubles (pas simples).

**I3. `build_ban_history.py` : deux remplacements non atomiques, sans sauvegarde** — `scripts/build_ban_history.py:204-208`.
`lists.to_sql(..., if_exists="replace")` puis `cards.to_sql(...)` : pandas valide chaque appel. Si le second échoue (verrou
`database is locked` après `timeout=60`, disque plein, interruption), `ban_backtest_lists` est neuve et `ban_backtest_cards`
ancienne : `GET /ban-radar/history` associe de nouveaux effectifs à d'anciennes cartes, sans erreur (lecture du code, non
reproduit). Écrit sur la base de référence, sans copie préalable (les autres lots ont des `backup_avant_*.db` faits à la main).
Correctif : une transaction explicite (`with conn:` autour de `DROP`/`CREATE`/`INSERT`, ou `to_sql` sur une connexion en
transaction unique), et passer par `--db` sur une copie quand on teste.

**I4. `deploy_prebuilt.py` ne vérifie pas la base lue par l'API du build** — `scripts/deploy_prebuilt.py:177-189`
(`check_api`). L'API locale interrogée au build peut lire `yugioh.db` (défaut de `db.py`) au lieu de `serving.db` : le script
affiche seulement un `warn` fixe, jamais un échec. Les pages construites (63 archétypes + decks) et l'API déployée peuvent alors
montrer des données différentes. `--execute` part quand même. Correctif : comparer une valeur sentinelle (ex. `computed_at`
de `/meta/tier-list`) à celle de `serving.db`, et en faire un `fail`. (Lecture du code, non reproduit.)

## Mineur

**M1. `limit` négatif non refusé** — `backend/app/routers/ban_radar.py:35` : `Query(..., le=200)` sans `ge=1`. Reproduit :
`limit=-1` renvoie 966 lignes (SQLite : `LIMIT -1` = sans limite), `limit=0` renvoie 0. Correctif : `ge=1`.

**M2. Caractères jokers de `LIKE` non échappés** — `backend/app/routers/cards.py:20,40` : `q=%` renvoie des cartes (reproduit :
200). Pas d'injection (paramètre lié), seulement un résultat inattendu. Correctif : échapper `%` et `_` avec `ESCAPE`.

**M3. `build_boutique_price_history.py` supprime la table avant de savoir s'il y a des lignes** —
`scripts/build_boutique_price_history.py:97-104`. `DROP TABLE` est validé tout de suite (le DDL n'ouvre pas de transaction en
`sqlite3` Python) ; si `card_price_history` est vide ou vient d'être renommée, la table servie devient vide, et un échec de
l'`INSERT` laisse une table vide. Correctif : sortir avec erreur quand `rows` est vide ; `BEGIN` explicite avant le `DROP`.

**M4. Slug vide possible** — `backend/app/slugs.py:23` : un archétype sans caractère ASCII donne `""` (aucun aujourd'hui :
231 archétypes, 0 vide, 0 collision, vérifié). `resolve` refuse bien un slug vide, mais `slugify` serait servi tel quel dans
`/decks` et `/archetypes` (lien `/decks/` cassé). Correctif : repli sur un identifiant stable si le slug est vide.

**M5. Recalcul de la tier list à chaque requête** — `backend/app/routers/decks.py:104`, `archetypes.py:61` :
`compute_tier_list` à chaque appel de `/decks` et `/archetypes/{slug}` (`/decks` : 0,29 s, `/archetypes/branded` : 0,01 s mesurés sur
`serving.db`), plus une requête d'image par archétype (`get_archetype_image`). Sans conséquence avec la revalidation de 300 s ;
à surveiller si l'API est appelée directement.

**M6. `rm -rf` autorisé sur tout ce qui est sous un worktree, même le worktree courant** — `garde_fou.py:57-60` :
`cible_autorisee` résout contre le `cwd` ; depuis un worktree, `rm -rf data` ou `rm -rf .` passent (voulu pour nettoyer, mais
`data/` y contient parfois un lien vers la base de référence). Les liens symboliques ne sont pas résolus (`normpath`, pas
`realpath`). Correctif : `realpath` avant le test.

**M7. `wilsonInterval` avec k NaN** — `frontend/src/lib/wilson.ts:28` : `Math.min(Math.max(NaN, 0), n)` = NaN, la bande
devient NaN (et `fmtNum` écrit « NaN »). Les champs viennent d'entiers de l'API, donc sans cas réel aujourd'hui. Correctif :
`if (!Number.isFinite(k)) return [0, 1]`.

**M8. Hébergement des images sur Vercel : 404 silencieuse** — `frontend/src/app/card-images/[...path]/route.ts:16-24` : sans
`CARD_IMAGES_DIR` ni dossier, la route renvoie 404 sans journal. Sans conséquence si `NEXT_PUBLIC_CARD_IMAGES_URL` est renseignée
(la route ne reçoit plus rien) ; sinon des cartes sans image sans trace dans les journaux. Correctif : `console.warn` une fois.
